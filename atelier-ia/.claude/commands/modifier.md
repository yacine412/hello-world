La personne demande une modification : $ARGUMENTS

1. Lis `node atelier.js etat <projet>` et les documents concernés.
2. Analyse l'impact en langage simple : ce qui change, les fonctionnalités, les données, les tests et le code touchés, les risques de casser ce qui marche.
3. Si la modification est importante, rédige le livrable `change` (analyse d'impact) : voir `/livrable`.
4. Enregistre les nouvelles décisions (`decision`, statut `proposed`) et les tâches (`task`). Ne réalise rien avant son accord.
